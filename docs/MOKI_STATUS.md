# MOKI (모두의 키오스크) 프로젝트 통합 상태 보드

이 문서는 집과 회사에서 Antigravity와의 대화 맥락을 끊김 없이 이어가기 위한 **프로젝트 상태, 기획안, 대화 기록 통합 문서**입니다. 새로운 기기에서 대화를 시작할 때 이 문서 하나만 읽히면 모든 컨텍스트가 복구됩니다.

---

## 📌 1. [우리의 개발 원칙]

1. **연속성 유지:** 이 통합 문서 기반으로 집과 회사의 개발 맥락을 완벽히 동기화합니다.
2. **유연한 기획 대응:** 기획안이나 목표가 변경되면 이 문서에 반영하여 방향을 조정합니다.
3. **백엔드 성장 파트너:** FastAPI 개발 시 **상세한 주석과 원리 설명**을 통해 멘토링을 제공합니다.

## 🛠️ 2. 현재 백엔드 진행 상태 (최근 업데이트: 2026-04-29)

- **완료된 기능:**
  - `User` 모델 및 Supabase 인증, 소셜 로그인 연동 (`social_login.py`)
  - 기본 CRUD 라우터 구축 (`Store`, `Category`, `Product`, `Order`, `Shelve`)
  - 기본 DB 아키텍처 및 CORS 설정 완료
  - 백엔드 환경 전면 정비 (`uv` 및 `SQLAlchemy 2.0` 기반, 멘토링 주석 강화 완료)
- **진행 대기 중인 다음 목표 (택 1):**
  - [ ] PortOne(포트원) 결제 연동 백엔드 로직 (오프라인 결제 승인, Webhook 처리 등)
  - [ ] 장바구니 및 다중 상품 주문(Order) 트랜잭션 로직 고도화
  - [ ] 파트너센터용 매출 통계 API 개발

## 💬 3. Antigravity 연결 프롬프트 (새 기기에서 복사/붙여넣기)

> 기존에 진행하던 MOKI 프로젝트를 이어서 할거야.
> 프로젝트 루트에 있는 `docs/MOKI_STATUS.md` (통합 상태 보드) 파일 하나만 끝까지 정독하고, 우리의 비즈니스 로직(기획안)과 핵심 개발 원칙, 최근 대화 기록을 완벽히 파악해줘.
> 파악이 완료되면, "진행 대기 중인 다음 목표" 중에서 오늘 시작할 코딩 작업을 나에게 제안해줘.

## 🚀 4. 상세 기획안 원문 (V2.1)

### [기획안] 범용 중고 키오스크 통합 솔루션 : 모두의 키오스크
*   **Version:** 2.1 (2026.05.04)
*   **Status:** 외식형 주문 출력 로직 최적화 버전

### 4.1 사업 개요 (Business Strategy)
*   **사업명:** 범용 중고 키오스크 솔루션 (모두의 키오스크)
*   **핵심 가치:** 중고 하드웨어의 자산 가치 재창출 및 소상공인 창업 비용 혁신적 절감.
*   **비즈니스 모델:** 사용 기간만큼 지불하는 SaaS 구독 모델 및 중고 기기 리퍼비시 렌탈 사업.

### 4.2 기술 스택 (Technical Stack)
*   **Backend:** Python (FastAPI), uv (환경 관리)
*   **Database/Auth:** Supabase (PostgreSQL, Real-time)
*   **Partner Web:** React (Vite) - 점주용 반응형 관리 페이지
*   **Kiosk Client:** Flutter (Windows/Android) - 크로스 플랫폼 앱
*   **Middleware:** PortOne V2 (오프라인 브릿지)
*   **Notice/Receipt:** Kakao AlimTalk (전자영수증) / POS Printer SDK (물리 출력)

### 4.3 프로그램 타입별 특화 로직 (Program Types)
*   **3.1 타입 A: 일반 상품 판매 (Retail)**
    *   **타겟:** 무인 아이스크림, 편의점, 소품샵 등.
    *   **주요 흐름:** 터치/바코드 스캔 → 장바구니 → 결제 → 고객 영수증 발행 → 종료.
    *   **특화 기능:** 바코드 리더기 연동, 상품 등록 시 바코드 스캔 지원.
*   **3.2 타입 B: 외식/푸드코트 (F&B) - [수정 반영]**
    *   **타겟:** 식당, 카페, 분식점 등 주문 번호 관리가 필요한 업종.
    *   **주요 흐름:** 터치 선택 → 옵션 설정 → 결제 → 2원화 출력(고객/주방) → 종료.
    *   **출력 프로세스 (Dual Output):**
        *   고객용 (Customer Side): 주문 번호가 적힌 영수증 발행 (종이 프린트 또는 카카오 알림톡 중 선택).
        *   주방용 (Kitchen Side): 주방 프린터로 주문서(상품명, 수량, 옵션, 주문 번호) 자동 전송 및 출력.
    *   **연동 기능:** DID(주문 현황판) 화면에 '준비중/완료' 상태 실시간 표시 연동.

### 4.4 기능 상세 정의 (Functional Specifications)
*   **4.1 키오스크 로컬 관리자 모드 (Local Admin Mode)**
    *   **진입:** 키오스크 화면 내 특정 영역 히든 터치 후 관리자 인증.
    *   **현장 조작:** 즉시 품절 처리, 재고 수량 조정, 긴급 가격 변경. 누적 매출 현황, 결제 취소(포트원 API 연동).
*   **4.2 영수증 및 주문서 발행 (Receipt & Order Sheet)**
    *   **카카오톡 전자영수증:** 휴대폰 번호 입력 시 알림톡으로 상세 내역 및 주문 번호 전송.
    *   **종이 영수증:** 키오스크 본체 프린터에서 주문 번호가 포함된 영수증 출력.
    *   **주방 주문서:** 외식형(Type B) 선택 시, 네트워크(LAN) 또는 시리얼 연결된 주방 프린터로 전송.
*   **4.3 파트너센터 (Partner Web Center)**
    *   **통합 관리:** 매장별 키오스크 작동 상태(Online/Offline) 실시간 모니터링.
    *   **타입 스위칭:** 매장 환경에 맞춰 '상품판매형' 또는 '외식형' 원격 설정 변경.
    *   **정산 관리:** 포트원 관리자 대시보드 연동을 통한 투명한 정산 데이터 제공.

### 4.5 안티그래비티 PM 에이전트 개발 지침
*   **지시사항 1: 다중 출력(Multi-Output) 로직 설계** (외식형 결제 완료 시 고객용/주방용 분기)
*   **지시사항 2: 로컬 설정값 저장 및 동기화** (네트워크 장애 대비 Local Storage 캐싱)
*   **지시사항 3: 바코드 및 프린터 드라이버 추상화** (ESC/POS 범용 라이브러리 사용)

## 📚 5. 이전 대화 기록 보관소

### 📅 2026-04-29 (백엔드 기본 환경 정비 및 최적화)

- **[요청 사항]** `pip` 대신 `uv` 사용, `SQLAlchemy 2.0` 최신 스펙을 적용하는 백엔드 전반 리팩토링 요청. PM/Backend 에이전트 보드 업데이트.
- **[진행 내용]** `docs/agents/02_BACKEND_TASKS.md`에 개발 원칙을 명문화. `database.py`의 세션 통합 및 엔진/세션 원리 주석 보강 완료. `main.py` 라우터와 정적 파일 서빙 정리 및 주석 강화. `models` 및 `routers` 내의 코드가 이미 `SQLAlchemy 2.0`(`Mapped`, `db.execute(select(...))`)을 준수하고 있음을 전수 확인.
- **[이슈 해결]** 로컬 DB 연결 테스트(`check_db.py`) 중 Supabase "Tenant or user not found" 연결 오류 발생을 확인하였고, 사용자가 Supabase 프로젝트 재활성화를 통해 즉시 해결 완료.
- **[다음 목표]** 다음 세션(회사 등)에서는 에이전트 연결 직후 '장바구니/주문(Order) 트랜잭션 고도화' 혹은 'PortOne(포트원) V2 오프라인 결제 연동 백엔드 로직 작성' 중 하나를 선택하여 바로 착수할 예정.

### 📅 2026-04-29 (프로젝트 초기 세팅 및 동기화 논의)

- **[요청 사항]** 사용자가 MOKI 프로젝트 기획안을 전달하며, 1) 집/회사 대화 연속성 유지 2) 기획안 업데이트 대응 3) FastAPI 백엔드 상세 주석 멘토링 등 3가지 원칙을 요구함.
- **[현황 진단]** AI가 현재 `c:\CODES\kiosk` 폴더를 분석하여 기본 인증 및 CRUD(User, Store, Product 등)가 Phase 1 수준으로 구축되었음을 확인함. 포트원 결제 연동이나 주문 트랜잭션 로직 고도화를 다음 단계로 제안함.
- **[동기화 솔루션 결정]** 사용자가 집-회사 간 대화 기록 동기화 방법을 문의함. AI는 클라우드 폴더 동기화 방식 대신, 가장 안전하고 코드와 완벽히 결합되는 **"GitHub를 통한 마크다운 문서 동기화"** 방식을 추천함. 사용자가 이를 수락함.
- **[보안 아키텍처 설명]** 웹 제미나이와 달리 안티그래비티는 사용자 로컬 소스 코드에 직접 접근하므로, 보안 및 정보 유출 방지를 위해 구글 클라우드에 대화 내용을 동기화하지 않고 철저히 로컬 기반(Local-First)으로 동작함을 설명함.
- **[통합 문서 생성]** 기획안 원문, 현재 상태, 다음 목표, 대화 기록을 모두 담은 현재의 단일 문서(`MOKI_STATUS.md`)를 생성하여 관리하기로 최종 협의함.
